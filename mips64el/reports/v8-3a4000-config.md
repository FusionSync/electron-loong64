# V8 / 3A4000 configuration review

Reviewed on 2026-11-10 while the Buster Electron build was running. This was a
read-only inspection of the existing `out/mips64el-buster` and selected source
files. No GN/Ninja command or additional build was started for this review.
The host `mksnapshot`, `snapshot_blob.bin` and `gen/v8/embedded.S` had not yet
been produced when inspected. These findings establish configuration, not
successful snapshot generation or target JavaScript execution.

The MIPS64R2 choice reaches V8's assembler/JIT, not only the native compiler:

- `src/v8/BUILD.gn:1531–1556` translates the MIPS architecture, float ABI,
  endian and optional MSA settings into V8 preprocessor definitions.
- `src/v8/src/codegen/mips64/constants-mips64.h:24–55` selects
  `kArchVariant=kMips64r2`, little-endian handling and
  `IsMipsSoftFloatABI=false` from those definitions. Macro-assembler and
  compiler backend code use `kArchVariant` to select pre-R6 instructions.
- `src/v8/include/v8config.h:858–909` defines the JIT target separately from
  the compiler host and gives MIPS64 a 64-bit target pointer size. Endian
  selection is at `:966–972`. The target triple uses N64, and the V8 MIPS64
  calling convention is N64 (`constants-mips64.h:1763–1767` and
  `register-mips64.h:231`). This does not select O32 or N32.
- `src/build/config/mips.gni:13` defaults `mips_use_mmi=false`; its non-Android
  MIPS64 defaults are R2 and MSA disabled. The selected generated definitions
  contain no MMI, MSA or R6 enablement.
- `src/v8/src/common/globals.h:54–55` enables the V8 simulator when the JIT
  target is MIPS64 and the compiler host is not. The host JSON's
  `simulator_run=false` is test-runner metadata calculated from
  `target_cpu != v8_target_cpu` (`src/v8/BUILD.gn:2833`); it does not disable
  this host snapshot simulator.

## Optional MSA code and runtime detection

`src/v8/src/snapshot/mksnapshot.cc:251` calls `CpuFeatures::Probe(true)`.
`src/v8/src/codegen/mips64/assembler-mips64.cc:76–80` uses only compiler-implied
features in that mode; it does not copy the host CPU's features into the target
snapshot. FPU is enabled by the target definitions. MSA is not a snapshot
baseline requirement.

`mips_use_msa=false` is not a promise that every generated byte is free of MSA
encodings. Upstream V8 emits guarded SIMD alternatives in builtins such as
`WasmCompileLazy` (`src/v8/src/builtins/mips64/builtins-mips64.cc:2921–2960`) and
deoptimization entry code (`:3648–3654`, `:3747–3753`, `:3849–3855`). These
alternatives use `kDontCheckSupported` while generating code, and are guarded
at execution by `supports_wasm_simd_128`. In this source,
`CpuFeatures::SupportsWasmSimd128()` returns `false`
(`assembler-mips64.cc:70–74`), selecting the double-register alternatives.
Their presence alone does not establish that unsupported instructions execute.

The native runtime also probes `/proc/cpuinfo` for `ASEs implemented: msa`
(`src/v8/src/base/cpu.cc:794–804`), and may record MSA support independently of
the GN flag (`assembler-mips64.cc:90–105`). The conservative baseline does not
depend on that feature. Runtime dispatch, JS deoptimization and scalar Wasm
still need target execution; configuration inspection cannot prove them.

## What the existing ELF audit can reject

[`scripts/audit-dist.py`](../scripts/audit-dist.py) requires ELF64, little-endian,
MIPS machine 8, MIPS64R2 `e_flags`, and N64 flags (`:29–39`). It then requires
MIPS64r2/GPR64/CPR1-64/hard-double attributes plus `ISA Extension: None` and
`ASEs: None` (`:40–48`). Correctly marked R6, Loongson/MMI or MSA inputs therefore
fail. GLIBC version, interpreter and absolute function-symbol checks add
separate runtime-library safeguards.

This is a metadata audit. It does not decode every executable instruction or
validate hand-emitted `.word`/byte sequences, raw embedded builtins, snapshot
data or machine code generated later by the JIT. A binary whose metadata
omits an extension can evade this specific check. The audit also skips
symlinks (`:84`) and records `DT_NEEDED` without recursively resolving the
system dependency graph (`:60–61`). It is one release gate, not a complete
instruction-set or runtime proof. A blanket byte search for MSA would also
misclassify the upstream guarded alternatives described above.

## Next execution check

The [offline runtime smoke](../tests/runtime-smoke/README.md) confirms optimized
JS and a number-to-string deoptimization, floating point, scalar Wasm, BigInt,
Intl, crypto/TLS initialization, file I/O, worker threads/shared atomics and
localhost HTTP. It can run through `ELECTRON_RUN_AS_NODE=1` with QEMU's
`Loongson-3A4000` CPU and the full Buster root once target Electron exists.
Its instructions use target-only `LD_LIBRARY_PATH`, bounded execution and
machine-readable output. The script is separately checked on host Node 22;
that host result is not MIPS validation. The MIPS Electron command has not yet
been executed, and GUI/GPU/sandbox and physical hardware remain separate checks.

The recorded host run used Node 22.23.3 / V8 12.4.254.21 on x86_64. All ten
cases passed; the optimized loop and addition status were `81`, and the type
change reduced the addition status to `1`. Temporary files were removed. The
[JSON result](../tests/runtime-smoke/host-node22-validation.json) explicitly
records `target_executed=false`.
